# HelloAgents: 从零构建的轻量级 Agent 教学框架

[![Python](https://img.shields.io/badge/Python-3.10+-blue)](https://www.python.org/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

**教学友好 · 极简可读 · 易扩展** — 帮助你真正理解 Agent 系统的内部运作

---

## 🎯 项目哲学

HelloAgents 不是生产级重型框架，而是一套 **“乐高积木”**：
- 核心模块 < 1000 行，无黑魔法
- 每个组件都可独立理解
- 从 SimpleAgent 到 ReAct，逐步构建认知

### 为什么自建框架？

| 市面框架痛点 | HelloAgents 方案 |
|-------------|------------------|
| 黑盒严重，难追踪 | 完全开源，代码可读 |
| 依赖臃肿，升级易崩 | 仅依赖 Pydantic + requests |
| 定制困难 | 继承基类，50 行加新功能 |
| 抽象过度 | 设计决策公开，注释详尽 |

### 五大核心设计原则

- **🎯 极简主义**：代码可读性 > 功能完备性
- **🔌 统一抽象**：LLM、Agent、Tool 均采用标准接口
- **🏗️ 开闭原则**：对扩展开放，对修改关闭
- **📖 教学导向**：每个模块独立可测
- **🔄 渐进兼容**：支持本地/云模型无缝切换

## 🏗️ 整体架构

```
用户输入
    ↓
Config (全局配置 · 单例模式)
    ↓
Agent 基类 (模板方法模式 · run 接口)
    ↓
LLM 层 (多厂商兼容 · 自动检测)
    ↓
Tool 系统 (万物皆工具 + Registry + Chain)
    ↓
消息历史 (Message 类 · 可持久化)
    ↓
最终输出 + 反思/迭代
```

### 核心抽象层（复习要点）

#### 📦 Config 类
- **作用**：全局配置管理中心
- **设计**：Pydantic + 单例模式
- **特性**：支持 `.env` 文件覆盖、类型校验

#### 💬 Message 类
- **作用**：统一消息格式
- **字段**：content, role, timestamp, tool_call_id, metadata
- **方法**：to_dict() → OpenAI 兼容格式

#### 🧬 Agent 基类
- **设计模式**：模板方法模式
- **核心方法**：`run()` 是模板，子类实现 `_execute()`
- **通用功能**：消息历史管理、流式输出、历史清空

## 🤖 LLM 扩展层

### 设计动机
支持任意大模型，避免框架绑死 OpenAI。用户只需改 `.env`，无需改代码。

### 自动检测机制（优先级）
1. 显式指定 provider
2. base_url 特征匹配（`localhost:11434` → Ollama）
3. api_key 格式猜测（`sk-` → OpenAI）

### 支持模型类型
- **OpenAI**：GPT 系列
- **Ollama**：本地零配置
- **vLLM**：高吞吐推理
- **可扩展**：Gemini、Claude、DeepSeek 等

## 🧠 Agent 范式（5 种经典）

| 范式 | 核心思想 | 适用场景 |
|------|---------|---------|
| **SimpleAgent** | 基础 LLM 调用 + 可选工具 | 简单对话、单轮任务 |
| **ReActAgent** | 思考 → 行动 → 观察 循环 | 需要多步推理的任务 |
| **ReflectionAgent** | 执行 → 反思 → 优化 | 需要高质量输出的场景 |
| **PlanAndSolveAgent** | 先规划步骤，再逐一执行 | 复杂任务分解 |
| **FunctionCallAgent** | 原生工具调用 + 参数解析 | 需要精确参数的工具调用 |

### 各范式核心流程（复习）

**ReActAgent 循环**：
```
1. 模型输出 Thought（思考）
2. 解析 Action（行动）
3. 如果是工具调用 → 执行 → 返回 Observation（观察）
4. 继续循环直到 Final Answer
```

**ReflectionAgent 流程**：
```
1. 生成初始回答
2. 让模型反思自己的回答（找问题）
3. 根据反馈优化回答
4. 重复 2-3 直到满意
```

**PlanAndSolveAgent 流程**：
```
1. 将任务分解为步骤列表
2. 依次执行每个步骤
3. 汇总各步骤结果
```

## 🔧 工具系统

### 核心设计：万物皆工具

**BaseTool 抽象类**：
- 属性：`name`, `description`, `parameters` (JSON Schema)
- 方法：`execute(params)` → str
- 方法：`to_schema()` → OpenAI 函数调用格式

### 三大组件

#### 1. ToolRegistry（注册中心）
- 功能：注册、获取、执行工具
- 核心方法：`register()`, `get()`, `execute()`
- 辅助方法：`get_descriptions()`（给模型看）, `get_openai_schema()`（给 OpenAI 用）

#### 2. ToolChain（工具链）
- 功能：串联多个工具顺序执行
- 特性：支持变量替换（`{{prev_output}}`、`{{step_0}}`）
- 适用：固定流程的任务（如：搜索 → 总结 → 翻译）

#### 3. AsyncToolExecutor（异步执行）
- 功能：线程池并行执行工具
- 适用：多个独立工具同时调用（如：同时查天气和查新闻）

## 📊 项目优劣势（复习）

### ✅ 优势
- **教学价值极高**：代码短小、逻辑清晰，新手 1-2 天看懂
- **扩展性强**：新增 Agent 或 Tool 只需继承
- **极轻量**：无重依赖，pip install 即用
- **兼容性好**：OpenAI 接口 + 支持多 LLM

### ❌ 局限性
- 无高级特性（长期记忆、多模态、分布式）
- Tool 返回 str 限制结构化数据表达
- 性能未深度优化（无缓存、无 GPU 加速）

## 🎯 面试面经（高频考点）

### 一、基础概念类

#### Q1：什么是 Agent？和 LLM 有什么区别？
**答**：LLM 是大脑，Agent 是大脑+手脚。LLM 只负责生成文本，Agent 能：
- 自主规划任务步骤
- 调用外部工具（搜索、计算、API）
- 记忆对话历史
- 根据反馈自我修正

#### Q2：ReAct 范式的核心思想是什么？
**答**：将推理和行动交织进行。每个循环：
1. **Thought**：思考当前状态和下一步该做什么
2. **Action**：执行一个具体行动（工具调用或给出答案）
3. **Observation**：观察行动结果，进入下一轮思考

#### Q3：什么是工具调用（Function Calling）？
**答**：模型输出结构化参数，框架负责执行对应函数并返回结果。关键点：
- 需要给模型提供工具的描述和参数 schema
- 模型学会在需要时“请求”调用工具
- 返回结果后再让模型生成最终回答

### 二、架构设计类

#### Q4：如何设计一个可扩展的 Agent 框架？
**答**：核心是“面向接口编程”：
- **LLM 抽象层**：统一 chat/stream 接口，支持多厂商
- **Tool 抽象层**：所有功能继承 BaseTool，统一 execute 接口
- **Agent 基类**：模板方法模式，run 固定流程，_execute 由子类实现
- **注册中心**：集中管理所有工具，方便动态获取

#### Q5：如何实现“万物皆工具”？
**答**：将所有功能模块都包装成 Tool：
- Memory 工具：读写记忆
- RAG 工具：检索知识库
- 计算工具：执行数学运算
- API 工具：调用外部服务
统一接口后，Agent 无需区分“这是什么类型的功能”，只管调用 execute。

#### Q6：如何处理工具调用的错误？
**答**：多层容错机制：
1. **工具内部 try-catch**：捕获异常，返回友好错误信息
2. **Registry 层捕获**：工具不存在或参数错误时返回标准错误格式
3. **Agent 层重试**：根据错误信息决定是否重新调用或换工具
4. **最终兜底**：告诉用户“暂时无法完成”

### 三、实现细节类

#### Q7：如何解析模型输出的工具调用？
**答**：支持多种格式：
- **JSON 格式**：`{"tool": "search", "params": {"q": "weather"}}`
- **XML 格式**：`<tool name="search"><param name="q">weather</param></tool>`
- **自然语言**：正则匹配“我想搜索一下天气”
生产环境推荐 JSON 或 OpenAI 原生 function calling。

#### Q8：如何管理多轮对话的历史？
**答**：
- 使用 Message 类统一格式，存入列表
- 支持滑动窗口（只保留最近 N 轮）
- 可持久化到数据库（SQLite/Redis）
- 关键：tool 调用记录也要存入历史，让模型知道上下文

#### Q9：如何实现流式输出？
**答**：
- LLM 层实现 `stream_chat()` 返回生成器
- Agent 层实现 `stream_run()` 逐字返回
- 前端可以实时展示“正在思考...”效果
- 注意：流式时工具调用通常需要等完整输出再解析

### 四、优化与挑战类

#### Q10：Agent 循环陷入死循环怎么办？
**答**：
- **最大步数限制**：`max_steps=10` 强制终止
- **重复检测**：如果连续 3 次相同 thought，主动终止
- **成本控制**：累计 token 超限时停止
- **人工干预**：提供“停止”按钮或接口

#### Q11：如何提高工具调用的准确性？
**答**：
1. **清晰的工具描述**：告诉模型什么时候用、怎么用
2. **参数示例**：在 description 里加示例
3. **few-shot 示例**：在 system prompt 里给几个例子
4. **模型选择**：使用支持 function calling 的模型（GPT-4、Claude-3）
5. **验证层**：参数不符合 schema 时自动修正或提示重试

#### Q12：多工具协同工作时如何避免冲突？
**答**：
- **工具链（ToolChain）**：定义固定执行顺序
- **依赖声明**：工具 A 的输出作为工具 B 的输入
- **变量替换**：用 `{{step_0}}` 引用前序结果
- **并行执行**：独立工具用 AsyncExecutor 同时运行

### 五、对比分析类

#### Q13：HelloAgents 和 LangGraph/AutoGen 的区别？

| 维度 | HelloAgents | LangGraph/AutoGen |
|------|------------|-------------------|
| **定位** | 教学框架 | 生产级框架 |
| **代码量** | < 1000 行 | 数万行 |
| **学习曲线** | 平缓，1-2 天 | 陡峭，数周 |
| **扩展方式** | 继承基类 | Graph/Flow 配置 |
| **适用场景** | 学习、实验、原型 | 复杂生产系统 |
| **依赖** | 极简 | 繁多 |

#### Q14：什么时候该自建 Agent 框架？
**答**：
- ✅ 想深入理解 Agent 原理
- ✅ 教学或培训需要
- ✅ 特定场景需要极致轻量
- ✅ 现有框架无法满足定制需求
- ❌ 生产级复杂应用 → 用成熟框架
- ❌ 资源有限不想维护 → 用成熟框架

### 六、场景应用题

#### Q15：设计一个“研究助手”Agent，需要哪些组件？
**答**：
1. **LLM**：GPT-4 或 Claude（强推理能力）
2. **工具集**：
   - WebSearchTool：搜索最新信息
   - CalculatorTool：数据分析
   - SummarizerTool：长文总结
   - SaveTool：保存结果到文件
3. **范式选择**：PlanAndSolve（先规划研究步骤）
4. **记忆**：保存搜索历史和中间结果
5. **反思**：每步结束后自我评估是否需要补充

#### Q16：如何测试 Agent 的可靠性？
**答**：
1. **单元测试**：测试每个工具单独工作
2. **集成测试**：测试完整流程，mock 外部 API
3. **黄金数据集**：准备 100 个典型问题，人工标注理想回答
4. **自动化评估**：用 GPT-4 给回答打分（1-5 分）
5. **边界测试**：模糊输入、空输入、超长输入
6. **压力测试**：同时运行多个 Agent，检查资源占用

## 🚀 快速开始

```bash
# 1. 安装
pip install hello-agents

# 2. 配置 .env
echo "OPENAI_API_KEY=sk-..." > .env

# 3. 运行示例
python examples/basic_agent.py
```

1. **配置**：Config 读取 .env
2. **注册**：ToolRegistry 注册工具
3. **创建**：Agent.create(范式, 配置, 工具)
