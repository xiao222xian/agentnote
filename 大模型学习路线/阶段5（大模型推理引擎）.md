# 怎么学（学前必读）

## 一、LLM 推理框架核心技术原理和实战

这一阶段的目标不是只会“启动一个模型服务”，而是：

> 从原理、代码、框架和实验四个层面，理解大模型推理系统为什么会快、为什么会慢、以及怎样优化。

---

### 第一部分：先建立整体推理系统认知

建议先看吴恩达和 DeepLearningAI 推出的大模型高效部署课程。  
这个课程和 Predibase 合作，内容质量很高，适合用来建立推理系统的全景认识。

重点理解：

- KV Cache
- Batch 与 Batch size 的影响
- Continuous Batching
- 多 LoRA 并发推理
- 显存瓶颈
- 推理延迟与吞吐率的基本概念

建议配合课程代码一起看，最好能自己动手跑一遍。

补充推荐：

- Efficiently-Serving-LLMs
- KV Cache 相关讲解与图解资料

要求至少做到：

- 讲清楚什么是 KV Cache
- 为什么推理是 memory-bound 场景居多
- 为什么 batching 能提升吞吐但不一定降低单请求延迟

---

### 第二部分：手写大模型推理，理解底层执行流程

建议精读 `karpathy/llama2.c`。

这个项目的重要性在于：

- 可以帮助你理解大模型推理到底在做什么
- 能把模型图和代码真正对上
- 能从底层语言角度看明白一个完整推理过程

建议目标：

- 至少看懂 tokenizer / embedding / attention / sampling 的主流程
- 看懂 KV Cache 在代码里是如何管理的
- 看懂一个 token 是怎样一步步算出来的

如果直接看 C 代码有难度，可以配合解读文章一起看。

> 这一部分非常锻炼 AI Infra 的基本功。  
> 如果你以后想做推理平台、推理优化、框架开发、CUDA 方向，这一步几乎绕不开。

---

### 第三部分：量化技术原理与实战

然后学习大模型量化技术。

要求掌握：

- weight-only quantization 是什么
- int4 / int8 是怎么做的
- GPTQ 是什么
- AWQ 是什么
- QLoRA 和推理量化的区别
- 量化之后为什么能省显存、提速度
- 量化为什么可能会带来精度损失

#### 学习建议

如果基础较薄弱，可以先补：

- 大模型量化基础知识
- GPTQ / AWQ 背后的基本思想
- 量化误差来自哪里

然后完成一个基础实战：

- 选一个模型，例如 `Qwen2.5-7B-Instruct`
- 分别完成：
  - INT4-AWQ 量化
  - INT4-GPTQ 量化
- 比较量化前后：
  - 显存占用
  - 推理速度
  - 输出质量

#### 环境建议

建议准备：

- 至少 32G V100 或 40G A100
- 或更高显存 GPU

推理量化常用工具可包括：

- autoAWQ
- llm-compressor

---

### 第四部分：学习推理加速实用技术

建议看商汤工程师的推理加速视频。  
里面会讲到很多更“工业界”的实战技术，例如：

- kernel 优化
- 显存访问优化
- 算子融合
- attention 加速
- batching 调度
- cache 管理

这一部分很适合反复看，因为很多面试题、工程优化思路都来自这里。

---

### 第五部分：掌握主流推理框架

理解了原理之后，必须真正上手至少一个主流推理框架。

本阶段重点建议掌握：

- **vLLM**
- **TensorRT-LLM**（至少了解）

现实工作中，这两个框架都非常常见：

- vLLM：开源、生态强、上手快、社区活跃
- TensorRT-LLM：工业级、性能高、NVIDIA 体系很常见

建议至少做到：

- 会部署 1~2 个模型
- 会压测吞吐
- 会看显存占用
- 会做简单参数调优

例如可以部署：

- LLaMA2-7B
- Qwen2.5-7B

并对比加速前后的效果。

---

### 第六部分：重点理解 FlashAttention

这部分必须掌握原理。

要求至少理解：

- FlashAttention 在解决什么问题
- 为什么它能降低 HBM 访问
- 它和普通 attention 的区别
- FlashAttention1 / FlashAttention2 的主要思路

推荐结合：

- 论文
- 图解博客
- 视频
- 手写 Self-Attention 的代码

建议目标：

- 能从 IO-aware 的角度解释它为什么快
- 能解释它和算子融合、内存访问优化的关系

---

### 第七部分：理解 vLLM 底层实现

对于很多同学来说，知道 “vLLM 很快” 还不够，必须知道它 **为什么快**。

重点学习：

- PagedAttention
- BlockManager
- Prefix Caching
- Scheduler
- Continuous Batching

推荐做法：

1. 先看 vLLM 源码讲解
2. 再看图解系列
3. 再自己启动 vLLM 做实验
4. 最后把原理和实验结果对应起来

> 面试时，如果你能把 “会用 vLLM” 和 “能讲清楚 vLLM 为什么快” 区分开来，竞争力会明显提升。

# 其他注意事项

1. 本阶段偏工程，不要求你一次看懂所有 CUDA 细节，但一定要建立“为什么快”的直觉。
2. 不要只会跑框架，要学会分析：

   * 延时为什么降了
   * 吞吐为什么涨了
   * 显存为什么省了
3. 实验报告一定要写出：

   * 环境
   * 模型
   * 参数
   * 并发设置
   * 度量指标
   * 结果解释
4. 如果做不动 TensorRT-LLM，不影响主线学习，优先保证 vLLM 跑通。
5. 面试常常会把：

   * vLLM
   * PagedAttention
   * FlashAttention
   * KV Cache
   * 动态 batching
     放在一起考，建议系统串起来理解。
